# UI 評価（2026-09）— 個人愛好家 / 事業者の観点

実装済み 28 画面を、デモデータ入りの開発サーバーで実際に描画して評価した記録。
ペルソナは [ユーザーペルソナ.md](./ユーザーペルソナ.md) の P1〜P7 を、
「個人（趣味で数鉢〜十数鉢）」と「事業者（盆栽園・生産者・多鉢運用）」の 2 軸に束ねて見ている。

評価の結果、**明らかに直すべきもの**は本ドキュメントと同じ PR で修正済み（§2）。
判断を伴うものは提案として §3 に残す。

## 1. 総評

| 観点 | 個人 | 事業者 |
|------|------|--------|
| 初回体験 | 登録 → 品種選択で「今月のやること」が自動で並ぶ導線は強い。ただし登録フォームの説明が無く、品種を選ぶ意味が伝わらなかった（修正済み） | 十数鉢をまとめて登録する手段が無い（提案 A-1） |
| 日々の記録 | 最頻の潅水がフォーム 1 枚分の手間。日時初期値が空欄になる不具合もあり、毎回入力させていた（修正済み・ワンタップ記録を追加） | 一括記録はあるが「すべて選択」「品種でまとめて選択」が無く、30 鉢分をタップさせていた（修正済み） |
| 記録の見返し | ログ一覧に検索しか無く、鉢ごと・作業ごとに追えない（修正済み） | 帳票・引き継ぎ用の書き出しが無い（CSV を追加） |
| 見た目の一貫性 | ホーム・詳細は新デザイン、ログ・フォーム・認証は旧配色（emerald）で別アプリに見える（修正済み） | 同左 |
| 情報量 | 問題なし | 品種マスタ由来の ToDo が鉢数分並び、ホームが縦長になる（先頭 5 件に折りたたみ） |

## 2. この PR で修正したもの

### 不具合
1. **作業ログの実施日時が空欄で開く** — `datetime-local` に Django 既定の `"YYYY-MM-DD HH:MM:SS"` を渡していたためブラウザが値を捨てていた。ISO（`T` 区切り）で描画する `DateTimeLocalInput` を共通化し、新規記録は「今」を初期値にした。
2. **タグ選択・一括記録のチェックボックスが崩れる** — 入力欄用の枠クラスが選択肢群のラッパー `div` と各 `input` の両方に付いていた。選択肢群はタップしやすいカード型で 1 つずつ描画する共通パーシャルに変更。
3. **品種詳細の作業種別が英語の生値**（`bud_pinching`）で表示されていた — 日本語ラベルに解決。当月の行をハイライト。
4. **ヘッダーの通知ベルが押しても何も起きない** — 通知設定画面へのリンクにした（配信は Phase 3）。

### デザイン統一
- 旧配色（emerald / gray、`rounded-md`）のまま残っていた画面を Material Design 3 トークンに統一:
  作業ログ一覧 / 記録 / 詳細 / 削除、スケジュール作成 / 削除、盆栽登録 / 削除、品種詳細、ログイン / 新規登録 / ログアウト。
- フォーム部品の共通クラス（`TailwindFormMixin`）もトークン色に変更したため、以降のフォームは自動で揃う。
- 削除リンクを詳細ヘッダーの目立つ位置から編集画面の末尾へ移し、誤タップを減らした。

### 個人向けの使いやすさ
- **クイック記録**: 盆栽詳細の上部に「潅水 / 葉水 / 観察を記録」ボタン。フォームを開かず「今」の日時で 1 タップ記録し、メッセージから詳細の追記へ進める。
- **ホームの ToDo 折りたたみ**: 先頭 5 件を表示し、「残り n 件を表示」で展開。
- **ログ一覧にサムネイル / 作業アイコン**: 写真の有無が一目で分かる。

### 事業者向けの使いやすさ
- **ログの絞り込み**: 盆栽 / 作業種別 / 期間。詳細タブの「この盆栽のログをすべて見る」から鉢単位で辿れる。
- **ログの CSV エクスポート**: 絞り込み条件のまま書き出し（UTF-8 BOM、Excel 対応）。
- **一括記録の選択補助**: 「すべて選択 / 解除」、品種ごとの「この品種を選択」、選択件数の表示。
- **ホームのグループ見出しから一括記録**: 品種別 / タグ別表示の見出しに「この n 鉢に一括記録」導線。

## 3. 提案（判断が要るため未実装）

### A. 事業者向け
| # | 提案 | 背景 |
|---|------|------|
| A-1 | **CSV / スプレッドシートからの一括登録**（盆栽・タグ） | 数十〜数百鉢の初期投入をフォームで行うのは現実的でない |
| A-2 | **置き場所（棚番号）フィールド** | 現状はタグで代用。事業者は「棚 3-B」のような固定属性で探す。タグと分けたほうが検索・一覧が安定する |
| A-3 | **QR コード / ラベル印刷** | 鉢に貼って詳細を開く。多鉢運用の定番機能 |
| A-4 | **預かり管理（顧客・預かり期間・返却予定）** | 盆栽園の主要業務。`BonsaiPlant` に所有者区分と顧客参照を足す設計が必要 |
| A-5 | **複数スタッフでの共同管理（組織・権限）** | 現状は 1 ユーザー = 1 コレクション。データモデルの変更を伴う |
| A-6 | **在庫・販売（価格、入荷 / 売却日）** | 事業者が「管理」に期待する範囲だが、趣味向けの画面を汚さない切り分けが要る |

### B. 個人向け
| # | 提案 | 背景 |
|---|------|------|
| B-1 | **ホームからの潅水ワンタップ**（カード上のボタン） | 現在は詳細画面のみ。カード全体がリンクのため、ボタンの入れ子構造を再設計する必要がある |
| B-2 | **PWA 化（ホーム画面に追加・オフライン閲覧）** | ベランダで開く用途。manifest とアイコン、サービスワーカーの追加 |
| B-3 | **写真の複数枚アップロードとカメラ起動** | 1 枚ずつのフォームは記録派に不便 |
| B-4 | **通知（Phase 3）** | 「今月のやること」の未完了を月半ばに知らせるだけでも継続率に効く |
| B-5 | **品種選択の検索付き入力** | 品種マスタが増えるとプルダウンでは探せない |

### C. 横断
| # | 提案 | 背景 |
|---|------|------|
| C-1 | **PC 幅のレイアウト** | 事業者は PC で使う場面が多い。現状は中央 `max-w-screen-md` の 1 カラム |
| C-2 | **Tailwind をビルド済み CSS に切り替え** | CDN 依存は本番運用に不向き（`base.html` の TODO）。プレビュー撮影で同等ビルドが通ることは確認済み |
| C-3 | **AI 連携（写真からの状態判定）** | 検討中・保留。方針は [サイトマップ §13](./サイトマップ.md) を参照 |
